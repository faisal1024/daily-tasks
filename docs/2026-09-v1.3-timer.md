# 1.3: A timer that lives on your tasks

Owner feedback (2026-09-29): the focus timer "doesn't integrate with the app".
Research (Llama Life, Tiimo, Sunsama): the best timers live *on the task*,
stay visible outside the app, and end with a decision instead of a dead stop.
Owner picked ideas **1, 2, 4, 5 and 8**.

Keep the app's tone: calm, no red, no guilt, no countdown panic.

## Shipping plan

| PR | Scope |
| --- | --- |
| E | One app-wide **session engine** (persisted). Timer on the task row and a "Now" bar (1). End check-in (4). 5-minute starter from the coach note (5). Focus screen becomes the detail view of the same session. |
| F | **Live Activity + Dynamic Island** with Done / Pause (2). **Start from the widget + Siri/Shortcuts** "Start my next task" (8). Native (Swift) work. |
| G | Expert **UI review** plus **UAT** in the iOS Simulator, then fixes. |

Every code PR: principal tester, three reviewers (architect + senior iOS,
usability and design, principal engineer), fix P1/P2, re-review, green CI.

## 1. Session engine (PR E)

There's one focus session at a time, app-wide. It's persisted, so it
survives an app kill, and mirrored to the App Group for the widget and
Live Activity.

```ts
type FocusSession = {
  id: string;
  taskId: string;
  taskText: string;           // snapshot for the Live Activity / widget
  stepText: string | null;    // a starter on a task's first step (after "Stuck?")
  date: string;               // yyyy-MM-dd; a session never crosses midnight
  kind: "timer" | "starter";  // starter = the 5-minute "just start"
  durationMs: number;         // current length (grows with "5 more minutes")
  startedAt: number;
  endAt: number | null;       // null while paused
  pausedRemainingMs: number | null;
  status: "running" | "paused" | "ended";
};
```

- The pure reducer and helpers live in `lib/daily-tasks/focus-session.ts`:
  - `startSession`, `pause`, `resume`, `extend(+5 min)`, `end`, `clear`;
  - `remainingMs(now)`;
  - rules: ticking the task clears the session; deleting the task, or
    choosing "Not today", clears it; a new day clears it; starting on
    another task replaces it.
- State lives in the store, is persisted and normalised, and is written to
  the App Group (key `focus.session`) whenever it changes.
- At launch a saved running session is restored first: an `endAt` further off
  than its length (the clock moved back) is pulled in to now + length, and
  one that ran out while the app was closed is already `ended` (nothing is
  scheduled for the past, and nothing is announced as if it just ended).
- The store marks a running session `ended` right when it runs out (a timer
  to `endAt`, and again when the app becomes active), so what's saved and
  mirrored says so; views derive the same from the clock in between.

### App Group mirror (built in PR E, read by PR F)

`lib/daily-tasks/widget-bridge.ts` → `writeFocusSession`, through the
existing `modules/widget-storage` bridge: App Group
`group.com.faisalislam.dailytasks`, key `focus.session`, a JSON string. It's
written when the store is ready and on every change (skipped when unchanged).
PR E doesn't reload the widget (nothing native reads it yet).

```jsonc
// No session:
null
// A session: the FocusSession above plus a version and a revision.
{
  "v": 1,
  "rev": 1790668800123,        // goes up with every write (at least the write's epoch ms)
  "id": "t_mg3k2x_ab12cd",
  "taskId": "t_mg3j9a_ef34gh",
  "taskText": "Walk the dog",
  "stepText": null,            // or the step's words for a step starter
  "date": "2026-09-29",
  "kind": "timer",             // "timer" | "starter"
  "durationMs": 1200000,       // grows with "5 more minutes"
  "startedAt": 1790668800000,  // epoch ms
  "endAt": 1790670000000,      // epoch ms; null while paused (and after ending from paused)
  "pausedRemainingMs": null,   // ms left while paused, else null
  "status": "running"          // "running" | "paused" | "ended"
}
```

Reading it natively: while `status == "running"`, the countdown is
`Text(timerInterval: now...endAt/1000)`; a running session whose `endAt` has
passed has ended even if the app hasn't written `ended` yet. For a progress
ring or bar, the current countdown started at `endAt - durationMs`, **not**
`startedAt` (a pause or "5 more minutes" moves the end; `startedAt` is when
the session began). Use `rev` to ignore an older state than one already shown. `v` changes only
for an incompatible shape. Commands from the Live Activity (Pause/Resume)
go through a separate queue (PR F); Done uses the widget's toggle queue, and
ticking the task clears the session when the app reconciles.
- Time is always timestamp-based. It's re-derived when the app becomes
  active.
- Notifications:
  - one end notification per session, rescheduled on pause, resume and
    extend; never for an end less than a second away, nor past the next local
    midnight (the session clears at midnight, so a notification after it would
    point at nothing); the first pass after launch reconciles (a stale one
    from a session that's gone is cancelled); the category is registered at
    every launch;
  - its category has actions **Done** and **5 more minutes** (expo-notifications
    categories);
  - a tapped action is handled by the app (response listener), including a
    cold launch; both buttons open the app (`opensAppToForeground`), since a
    background action is dropped when the app isn't running. Done ticks the
    task through the store (the celebration shows because Today is on screen);
    "5 more minutes" extends. Any tap on it shows Today. A tap for an old
    session is ignored;
  - no time-sensitive entitlement (it needs an Apple login to build).

## 2. Timer on the task and the "Now" bar (PR E, idea 1)

- **Starting a timer:** each open task row gets a compact **▶** (44pt
  target, a quiet icon, next to the row's existing actions; don't crowd
  the hero row). Tapping it offers **5 / 10 / 20 min / Custom…** (an
  action sheet on iOS; Custom opens the existing countdown wheel). The
  last-used length is listed first.
- **The running task's row** shows a small progress ring and the time left
  in place of ▶. Tapping it opens the focus screen.
- **The "Now" bar** is pinned under the Today header while a session exists.
  It shows:
  - the task text (one line), the time left, and Pause/Resume;
  - "Paused" while paused, and "Time's up" once it has ended;
  - it's tappable, opening the focus screen, and it's accessible.
- **The focus screen** (the existing `FocusMode`) now shows the *current
  session*. It no longer owns a separate timer:
  - closing it doesn't stop the timer, and "Not now" becomes "Close";
  - an explicit **Stop timer** ends the session;
  - with no session, it offers the 5/10/20/Custom choice.

## 3. End check-in (PR E, idea 4)

When a session reaches zero:

- If the app is open, the Now bar (and the focus screen, if open) turns
  into a calm check-in: **"Time's up on '<task>'."** with three choices:
  - **Done** ticks the task through the normal path, so the celebration,
    analytics and win-back all run;
  - **5 more minutes** extends the session;
  - **Stuck? Break it down** opens break-down for that task (the Plus gate
    as today), then offers a 5-minute starter on its first step.
- If the app is in the background, the notification carries the Done and
  "5 more minutes" actions.
- With no answer, the check-in stays until the user acts or closes it
  ("Not now" clears the session). It never auto-ticks.

## 4. The 5-minute starter (PR E, idea 5)

- The coach note's **Start** begins a 5-minute starter on the note's task.
  There's no length choice: one tap.
- The Now bar and focus screen say: "Just start. You can stop after 5."
- At the end the check-in reads: **"5 minutes in. Keep going?"**, offering
  **Keep going** (converts it to a 20-minute timer by default),
  **Done**, or **Stop here** (clears it, with no guilt copy).

## 5. Live Activity and Dynamic Island (PR F, idea 2)

- ActivityKit Live Activity, started when a session starts, updated on
  pause, resume and extend, and ended when the session clears (with a short
  "Done" state that is then dismissed).
- **Lock screen:** the task text, a ring or progress bar,
  `Text(timerInterval:)` counting down (it ticks on its own, with no
  updates), and the Done and Pause/Resume buttons (`LiveActivityIntent`,
  iOS 17+). The same brand colours as the widget, calm.
- **Dynamic Island:**
  - compact: a ring and the time;
  - minimal: a ring;
  - expanded: the task, the time, and Done/Pause.
- Buttons act without opening the app. They write to the App Group (the
  existing widget toggle queue for Done, and a session-command queue for
  Pause/Resume), update the activity, reschedule the end notification
  where possible, and the app reconciles when it next becomes active.
- `NSSupportsLiveActivities` goes in the app Info.plist. No push-based
  updates (no entitlement needed).

## 6. Start from anywhere (PR F, idea 8)

- **Widget:**
  - a **Start** button on the next open task (small and medium, Plus as
    today for interactivity);
  - it opens the app via `dailytasks://focus/start?task=next`, which starts
    a session (a 20-minute default, or the last-used length) and its Live
    Activity;
  - when a session is running, the widget shows it (the task and a
    `timerInterval` countdown).
- **Siri / Shortcuts:**
  - an App Shortcut "Start my next task" (also "Start a 5-minute starter")
    that opens the app into the same deep link;
  - `openAppWhenRun`, so the Live Activity can start from the app.
- The deep links are handled in the app (expo-router) and are idempotent.

## PR F: how it's built

### Native pieces

| Where | What |
| --- | --- |
| `targets/widget/FocusActivityShared.swift` = `modules/focus-activity/ios/FocusActivityShared.swift` | `FocusActivityAttributes` (+ `ContentState`), the mirror's decoder, the App Group queues, and the buttons' logic (`FocusActions`). **Two byte-identical copies** (the widget extension and the app's FocusActivity pod); ActivityKit pairs them by type name and shape. `tests/native-shared.test.ts` fails when they differ. |
| `modules/focus-activity` | Local Expo module: `areActivitiesEnabled`, `activeSessionIds`, `start(json)`, `update(json)`, `end(sessionId?, finalStatus?, dismissAfterSeconds)`. Starts activities on iOS 17+ only (the widget extension that draws them targets 17); guarded, ActivityKit weak-linked, the app still supports 15.1. Never throws into JS. |
| `lib/daily-tasks/live-activity.ts` | `syncLiveActivity(session, { ending, force })`, serialised. Called by the store on every session change and on each foreground (reconcile). |
| `targets/widget/FocusLiveActivity.swift` | Lock screen + Dynamic Island views. |
| `targets/widget/FocusIntents.swift` | The App Intents: Pause / Resume / Done (`LiveActivityIntent`, iOS 17), `StartFromWidgetIntent` (the small widget's Start), and, app only, `StartNextTaskIntent` / `StartStarterIntent`. |
| `native/app/FocusShortcuts.swift` | The `AppShortcutsProvider` (Siri, Shortcuts, Spotlight). |
| `plugins/with-focus-app-intents.js` | Config plugin: copies `targets/widget/FocusIntents.swift` and `native/app/*.swift` into `ios/<App>/` and adds them to the **app target's** Sources at prebuild. |

**Why a config plugin for the app target.** App Shortcuts are read from the
app bundle's App Intents metadata (`Metadata.appintents`), which Xcode's
`appintentsmetadataprocessor` extracts only for Swift compiled in the app
target itself, not from a pod / static library. An intent that opens the app
(`openAppWhenRun`) and a Live Activity's intent run in the app's process when
the app has them, so the same intent types must be in the app too.
`@bacons/apple-targets` only creates extension targets (its `app-intent` type
is a separate ExtensionKit extension, which can't host `openAppWhenRun`
intents or the app's shortcuts), so a ~60-line plugin adds the files to the
app target instead. `ios/` is generated (CNG); the copies are rewritten on
every prebuild. In the app, `FocusIntents.swift` gets the shared types from
`import FocusActivity` (`#if canImport(FocusActivity)`, which is also how the
file knows it's in the app: only there does it open the deep link and declare
the Siri intents).

`NSSupportsLiveActivities = YES` is set through `app.config.ts`
(`ios.infoPlist`). No push token, no new entitlements.

### Live Activity lifecycle (app side)

- **Start** when a session starts (running or paused), if
  `ActivityAuthorizationInfo().areActivitiesEnabled` and the app is in the
  foreground (a background start fails quietly; the next foreground retries).
- **Update** whenever what it shows changes: pause, resume, 5 more minutes /
  Keep going, the task's words, time's up. The content's `staleDate` is the
  countdown's end, so the views turn into "Time's up" on their own.
- **End** when the session goes: "Done" if its task was ticked, else "Timer
  stopped", shown for 8 seconds (`.after`), then dismissed. Replaced by
  another task's timer: the old one ends at once.
- **Reconcile** on every foreground: activities whose session is gone end at
  once; a running or paused session without one gets one again.

### Button queues (App Group)

The buttons never need the app. They run in the app's process when it can be
woken (else in the widget extension); either way they only touch the App
Group, ActivityKit and the notification centre:

- **Pause / Resume** update the mirror optimistically (a higher `rev`) and
  the activity, hold or re-schedule the end notification (a pause keeps its
  content in `focus.heldNotification*`, a resume re-adds it for the new end,
  never under a second away or past midnight), and append to
  **`focus.commands`**:

  ```jsonc
  // focus.commands (only native code writes it)
  [{ "seq": 7, "sessionId": "t_mg3k2x_ab12cd", "action": "pause", "at": 1790669100000 }]
  // focus.processedSeq (only the app writes it): the last seq it applied
  ```

  `seq` goes up by one from `max(queued, processedSeq)`; the queue keeps the
  last 50. The app applies the commands newer than `processedSeq` **before
  anything settles the session** (at launch, before `restoreSession`; on each
  foreground, and before the end timer settles it): each at its tap time (`at`,
  clamped to now), only for the current session (a stale one is dropped), and
  pause/resume are no-ops when already so, so replaying is harmless. Then it
  rewrites the mirror from its own state, re-syncs the activity and
  reschedules or cancels the end notification as usual.
- **Done** appends `{ seq, id: taskId, date, done: true, source: "live_activity" }`
  to the widget's **`widget.toggles`** (so the app ticks it with the normal
  side effects next time it's active, and the session clears), marks it done
  in `widget.snapshot` for the widget, removes the end notification, and ends
  the activity with "Done". A Done on yesterday's activity just ends it.
- A button on an activity whose session the app has moved past shows the
  app's state (or ends the activity if the session is gone).

`live_activity_action { action }` is sent when the app applies them.

### Start from anywhere

- `dailytasks://focus/start?task=next&source=widget|siri[&kind=starter]`.
  `app/+native-intent.tsx` catches it (cold start and while running), queues
  it in `lib/daily-tasks/focus-link.ts`, and shows Today; the store acts once
  it's ready.
- Siri's intents (`openAppWhenRun`) also leave `focus.startRequest`
  (`{ id, kind, source, at }`) in the App Group, because a cold start can miss
  the link; the app takes it once ready and on each foreground if it's under a
  minute old and not the last one handled (`focus.startHandled`). Both paths
  arriving for one run count once.
- What it does: the next open task (first open on today's list, as the
  widget shows it). No session: start it (the last length used, else 20
  minutes; `kind=starter`: the 5-minute starter), source "widget" / "siri".
  That task's timer already on (running, paused or at time's up): nothing,
  just Today. Another task's timer on: Today opens the next task's focus
  screen, which says a start there stops the other (never replaced silently).
  Nothing open: just Today.
- **Widget:** the Start button sits on the next open task: a `Link` beside it
  in the medium widget; in the small one (which can't hold a Link) a button
  whose intent opens the app (`StartFromWidgetIntent`, iOS 17). Shown for
  everyone (it only opens the app); ticking stays Plus. While a session is on
  (and its task is open), the small widget shows it (the countdown top right,
  "Now" / "Paused" / "Time's up" and its words) and the medium one's header
  becomes the countdown (or "Paused · 4:12 left" / "Time's up"). The timeline
  gets an entry at the session's end; the app reloads the widget on every
  mirror write.
- **Siri / Shortcuts:** "Start my next task" and "Start a 5-minute starter"
  (App Shortcuts, so they work with no setup).

## Analytics

- `focus_session_started { kind, minutes, source: "row" | "coach" | "widget" | "siri" | "focus" | "check_in" }`
  (`minutes` as started, after clamping; `check_in` is the starter offered after "Stuck?")
- `focus_session_ended { outcome: "done" | "extended" | "stopped" | "cleared" | "broken_down", minutes }`
  (`minutes` is the session's length at that point). One per countdown that
  ends: "extended" for 5 more minutes / Keep going (the session goes on);
  "stopped" for Stop timer, Not now and Stop here; "broken_down" for Stuck?;
  "done" when its task is ticked from anywhere; "cleared" when it goes
  otherwise (deleted, Not today, a new day, another task's timer).
- `focus_opened { source: "coach" | "row" | "now_bar" | "widget" | "siri" }`
  (widget / siri: a start from outside while another task's timer is on)
- `live_activity_action { action: "done" | "pause" | "resume" }`

Keep `focus_completed` for the Done button inside the focus screen.

## PR E decisions

- **Now bar placement:** first thing under the Today header, in the list
  (not sticky): Today is short, and a sticky bar would sit under the status
  bar once scrolled.
- **Coach Start** (owner's call) begins the starter and stays on Today (the
  Now bar and row show it). While that task's timer is on, the button reads
  **Open** and only opens the focus screen; it never restarts the timer.
- **Task row:** a timer icon on every open row (set days too), a 44pt target
  no taller than the circle, so rows don't grow; VoiceOver also gets a
  "Start timer" action on the row. The sheet reads `Focus on "<task>"` with
  5 / 10 / 20 minutes (last used first) and Custom…, and says
  `This stops the timer on "<other>".` when another task's timer is on (so
  does the focus screen above its lengths). On iPad it's a popover from the
  button. Android: the last used length, "Choose length…" (the focus
  screen's lengths) and Cancel.
- **Custom…** from a row opens the focus screen; the length wheel appears
  once the screen has finished sliding in (its first-spin fix needs it on screen).
- **Time's up never looks like done:** a full ring in the primary colour with
  a bell (row, Now bar) or "Time's up" (focus screen), never a green tick.
- **Check-in:** "Stuck? Break it down" shows only for a timer whose task has
  no steps yet and when the AI can be reached; the session stays until the
  break-down actually runs (closing the paywall keeps it). The starter it
  offers afterwards is an alert ("Start with the first step?"), so nothing
  starts on its own. The timer's "Not now" is **Stop here** (as for a starter).
- **"5 more minutes" on a starter** keeps it a starter: the check-in then
  reads "10 minutes in. Keep going?".
- The rating ask waits while a session is running or checking in (not while
  it's paused).
- The coach note shows no Start button while a timer runs on another task.
- A timer ending after midnight gets no end notification (sessions never
  cross midnight: it clears at the rollover).
- The focus screen's check-in has no Done of its own and its buttons are
  tinted: the screen's Done is the one solid button. While a timer runs its
  close button reads "Back to Today".
