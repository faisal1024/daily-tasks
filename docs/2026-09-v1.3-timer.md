# 1.3: A timer that lives on your tasks

Owner feedback (2026-09-29): the focus timer "doesn't integrate with the app".
Research (Llama Life, Tiimo, Sunsama): the best timers live *on the task*,
stay visible outside the app, and end with a decision instead of a dead stop.
Owner picked ideas **1, 2, 4, 5 and 8**.

Keep the app's tone: calm, no red, no guilt, no countdown panic.

## 1. Session engine (PR E)

There's one focus session at a time, app-wide. It's persisted, so it
survives an app kill, and mirrored to the App Group for the widget and
Live Activity.

```ts
type FocusSession = {
  id: string;
  taskId: string;
  taskText: string;           // snapshot for the Live Activity / widget
  stepText: string | null;    // a starter on a task's first step (after "Stuck?")
  date: string;               // yyyy-MM-dd; a session never crosses midnight
  kind: "timer" | "starter";  // starter = the 5-minute "just start"
  durationMs: number;         // current length (grows with "5 more minutes")
  startedAt: number;
  endAt: number | null;       // null while paused
  pausedRemainingMs: number | null;
  status: "running" | "paused" | "ended";
};
```

- The pure reducer and helpers live in `lib/daily-tasks/focus-session.ts`:
  - `startSession`, `pause`, `resume`, `extend(+5 min)`, `end`, `clear`;
  - `remainingMs(now)`;
  - rules: ticking the task clears the session; deleting the task, or
    choosing "Not today", clears it; a new day clears it; starting on
    another task replaces it.
- State lives in the store, is persisted and normalised, and is written to
  the App Group (key `focus.session`) whenever it changes.
- At launch a saved running session is restored first: an `endAt` further off
  than its length (the clock moved back) is pulled in to now + length, and
  one that ran out while the app was closed is already `ended` (nothing is
  scheduled for the past, and nothing is announced as if it just ended).
- The store marks a running session `ended` right when it runs out (a timer
  to `endAt`, and again when the app becomes active), so what's saved and
  mirrored says so; views derive the same from the clock in between.

### App Group mirror (built in PR E, read by PR F)

`lib/daily-tasks/widget-bridge.ts` → `writeFocusSession`, through the
existing `modules/widget-storage` bridge: App Group
`group.com.faisalislam.dailytasks`, key `focus.session`, a JSON string. It's
written when the store is ready and on every change (skipped when unchanged).
PR E doesn't reload the widget (nothing native reads it yet).

```jsonc
// No session:
null
// A session: the FocusSession above plus a version and a revision.
{
  "v": 1,
  "rev": 1790668800123,        // goes up with every write (at least the write's epoch ms)
  "id": "t_mg3k2x_ab12cd",
  "taskId": "t_mg3j9a_ef34gh",
  "taskText": "Walk the dog",
  "stepText": null,            // or the step's words for a step starter
  "date": "2026-09-29",
  "kind": "timer",             // "timer" | "starter"
  "durationMs": 1200000,       // grows with "5 more minutes"
  "startedAt": 1790668800000,  // epoch ms
  "endAt": 1790670000000,      // epoch ms; null while paused (and after ending from paused)
  "pausedRemainingMs": null,   // ms left while paused, else null
  "status": "running"          // "running" | "paused" | "ended"
}
```

Reading it natively: while `status == "running"`, the countdown is
`Text(timerInterval: now...endAt/1000)`; a running session whose `endAt` has
passed has ended even if the app hasn't written `ended` yet. For a progress
ring or bar, the current countdown started at `endAt - durationMs`, **not**
`startedAt` (a pause or "5 more minutes" moves the end; `startedAt` is when
the session began). Use `rev` to ignore an older state than one already shown. `v` changes only
for an incompatible shape. Commands from the Live Activity (Pause/Resume)
go through a separate queue (PR F); Done uses the widget's toggle queue, and
ticking the task clears the session when the app reconciles.
- Time is always timestamp-based. It's re-derived when the app becomes
  active.
- Notifications:
  - one end notification per session, rescheduled on pause, resume and
    extend; never for an end less than a second away, nor past the next local
    midnight (the session clears at midnight, so a notification after it would
    point at nothing); the first pass after launch reconciles (a stale one
    from a session that's gone is cancelled); the category is registered at
    every launch;
  - its title is the task's words (cut to 60 characters with "…"); its body
    is the question: a timer "Time's up. 5 more minutes, or mark it done?", a
    starter "5 minutes in. Keep going?" ("10 minutes in…" after 5 more);
  - two categories (expo-notifications), picked by the session's kind, extend
    on the left and Mark done on the right as everywhere else: a timer's
    `three-today:focus-session` (**5 more minutes**, **Mark done**) and a
    starter's `three-today:focus-starter` (**Keep going**, **Mark done**);
  - a tapped action is handled by the app (response listener), including a
    cold launch; the buttons open the app (`opensAppToForeground`), since a
    background action is dropped when the app isn't running. Mark done ticks the
    task through the store (the celebration shows because Today is on screen);
    "5 more minutes" extends a timer; Keep going makes a starter a 20-minute
    timer, as its check-in does (a notification from before 1.3's starter
    category, whose "5 more minutes" is on a starter, keeps going too, like
    the Live Activity's time's-up button). Any tap shows Today; a tap on the
    notification itself with the check-in due (the session at time's up)
    opens that session's focus screen (`focus_opened { source: "notification" }`),
    where the check-in is. A tap for an old session is ignored;
  - once a "Time's up" is answered anywhere it's cleared from Notification
    Center: in the app, on the Live Activity (its intents remove the
    delivered one natively), and again when the app applies those taps;
  - no time-sensitive entitlement (it needs an Apple login to build).

## 2. One timer, on the task (PR E, idea 1; revised)

Owner feedback (2026-09-29): Today showed **two timers** for one session,
the Now bar ("Write the quarterly · 4:17 left · ⏸") and the running row's
ring with "4:17". Owner's call: **one timer, on the task.** The Now bar is
gone; everything it did now lives on the task's row.

- **Starting a timer:** each open task row gets a compact **▶** (44pt
  target, a quiet icon, next to the row's existing actions; don't crowd
  the hero row). Tapping it offers **5 / 10 / 20 min / Custom…** (an
  action sheet on iOS; Custom opens the existing countdown wheel). The
  last-used length is listed first.
- **The running task's row** shows a **pill** in place of ▶: a small
  progress ring with **⏸** inside while running (**▶** while paused),
  then the time left ("4:17").
  - Tapping the pill **pauses or resumes** (the store's pause/resume, so
    the same notifications, Live Activity and analytics as before), with a
    selection haptic, and says "Paused" / "Resumed" politely.
  - The ring **drains**: it shows the time left, like Clock and the Live
    Activity (the focus screen's ring too).
  - Paused: the time stays frozen, the ring, time and outline go muted, the
    glyph is ▶, and the line under the task's words says just "Paused."
    (a starter's line goes while paused).
  - Look: no fill, a 1pt primary outline on the row's surface (so the time's
    contrast is the surface's, AA), 30pt tall so the row never grows; 44pt
    target from the hit slop; it lines up with the ▶ it replaces (−8pt right
    margin); its least width is 44pt × the text size (up to 1.3×). The
    time's width is set from the countdown's full length, so it doesn't
    reflow as it ticks. On narrow windows (under 360pt) it's the ring alone.
    Theme colours, so dark mode follows (live: the app follows the system's
    Light/Dark while it runs).
  - VoiceOver: a button, "Pause timer: <task>, 4 minutes left" / "Resume
    timer: <task>, 4 minutes left" (whole minutes, never every second), with
    the value "Running" / "Paused".
  - One clock per timed row: the pill, the line under the words and the
    check-in all read the same tick, so they never disagree.
  - Time's up: the pill is the full ring with a **bell** and no outline
    (never a green tick), "Time's up: <task>"; tapping it opens the focus screen.
- **Opening the focus screen:** tapping the timed task's **words** opens it
  (the detail view: Stop timer, steps, length). Those words normally open
  the row's menu (Edit, Not today, Break it down, Delete); while that task
  is timed, the menu is on a **long press** and leads with the timer's
  choices: **Open focus**, **Pause timer** / **Resume timer** (not at time's
  up), **Stop timer**, then the row's own actions (the swipe and VoiceOver
  actions are unchanged). Every action sheet (this menu, the lengths) is
  tinted with the primary. **Not today** on the timed task stops its timer
  and its note says so ("Saved for later. Timer stopped."). VoiceOver gets
  an **Open focus** action on the task's checkbox. Other rows keep their
  behaviour (▶ starts a timer). While it's timed, the hero row hides its
  "Break it down · Not today" line (the check-in, the focus screen and the
  long-press menu have them), and the steps under it have no "Clear steps".
- **Carried over** (yesterday's task) is a quiet muted label with a small
  arrow (not the amber warning colour, which was 1.8:1).
- **A starter's line:** "Just start. You can stop after 5 minutes." is the
  muted subtitle under the running task's words (with "Now: <step>" for a
  starter on a step after "Stuck?", which stays at time's up).
- **Time's up:** the check-in (§3) appears **inline, right under that task's
  row**, inside the tasks card and in line with the task's words: a short
  line ("Time's up." or a starter's "5 minutes in. Keep going?") and
  the check-in's buttons. No card of its own; the row's bottom padding
  drops to 8pt (the check-in's last line is a 44pt link). The links sit on
  the left under the buttons: "Stuck? Break it down · ✓ Mark task done" (just
  "✓ Mark task done" without a break-down). Its end is said politely (and
  felt) by Today's cues hook (`hooks/use-focus-session-cues.ts`).
- **The focus screen** (the existing `FocusMode`) now shows the *current
  session*. It no longer owns a separate timer:
  - closing it doesn't stop the timer; its one exit button reads "Back to
    Today" (see "PR H" below: at time's up **Take a break** replaces it);
  - an explicit **Stop timer** ends the session;
  - with no session, it offers the 5/10/20/Custom choice (under a "Timer"
    label; while a session runs the label goes and the ring sits in the
    middle of the space left);
  - Pause's VoiceOver hint is "Pauses the timer".

## 3. End check-in (PR E, idea 4)

When a session reaches zero:

- If the app is open, the task's row (and the focus screen, if open) shows
  a calm check-in: **"Time's up on “<task>”."** with these choices, extend
  first (left) and the lead (solid) one, as everywhere at time's up:
  `[5 more minutes (solid)] [Take a break (tint)]`, then the quiet links
  `Stuck? Break it down · ✓ Mark task done` (revised in PR H):
  - **5 more minutes** extends the session;
  - **Take a break** ends the session; the task stays open (on the focus
    screen it also goes back to Today);
  - **✓ Mark task done** ticks the task through the normal path, so the
    celebration, analytics and win-back all run;
  - **Stuck? Break it down** opens break-down for that task (the Plus gate
    as today), then offers a 5-minute starter on its first step.
- If the app is in the background, the notification carries the choices
  ("5 more minutes" and Mark done; a starter's Keep going and Mark done).
- With no answer, the check-in stays until the user acts. It never
  auto-ticks, and nothing but "Mark task done" / "Mark done" ever ticks.

## 4. The 5-minute starter (PR E, idea 5)

- The coach note's **Start** begins a 5-minute starter on the note's task.
  There's no length choice: one tap.
- The task's row (under its words) and the focus screen say: "Just start.
  You can stop after 5 minutes." (not while paused: then just "Paused.").
- At the end the check-in reads: **"5 minutes in. Keep going?"**, offering
  `[Keep going] [Stop for now]` (Keep going converts it to a 20-minute timer
  by default; Stop for now, a starter's Take a break, ends it, with no guilt
  copy) and the quiet **✓ Mark task done**.

## 5. Live Activity and Dynamic Island (PR F, idea 2)

- ActivityKit Live Activity, started when a session starts, updated on
  pause, resume and extend, and ended when the session clears (with a short
  "Done" state that is then dismissed).
- **Lock screen:** the task text, a ring or progress bar,
  `Text(timerInterval:)` counting down (it ticks on its own, with no
  updates), and Pause/Resume, or at time's up 5 more minutes / Take a break /
  Mark done (`LiveActivityIntent`,
  iOS 17+). The same brand colours as the widget, calm.
- **Dynamic Island:**
  - compact: a ring and the time;
  - minimal: a ring;
  - expanded: the task, the time, and the same buttons as the lock screen.
- Buttons act without opening the app. They write to the App Group (the
  existing widget toggle queue for Done, and a session-command queue for
  Pause/Resume), update the activity, reschedule the end notification
  where possible, and the app reconciles when it next becomes active.
- `NSSupportsLiveActivities` goes in the app Info.plist. No push-based
  updates (no entitlement needed).

## 6. Start from anywhere (PR F, idea 8)

- **Widget:**
  - a **Start** button on the next open task (small and medium, Plus as
    today for interactivity);
  - it opens the app via `dailytasks://focus/start?task=next`, which starts
    a session (a 20-minute default, or the last-used length) and its Live
    Activity;
  - when a session is running, the widget shows it (the task and a
    `timerInterval` countdown).
- **Siri / Shortcuts:**
  - an App Shortcut "Start my next task" (also "Start a 5-minute starter")
    that opens the app into the same deep link;
  - `openAppWhenRun`, so the Live Activity can start from the app.
- The deep links are handled in the app (expo-router) and are idempotent.

## PR F: how it's built

### Native pieces

| Where | What |
| --- | --- |
| `targets/widget/FocusActivityShared.swift` = `modules/focus-activity/ios/FocusActivityShared.swift` | `FocusActivityAttributes` (+ `ContentState`), the mirror's decoder, the App Group queues, and the buttons' logic (`FocusActions`). **Two byte-identical copies** (the widget extension and the app's FocusActivity pod); ActivityKit pairs them by type name and shape. `tests/native-shared.test.ts` fails when they differ. |
| `modules/focus-activity` | Local Expo module: `areActivitiesEnabled`, `activeSessionIds`, `start(json)`, `update(json)`, `end(sessionId?, finalStatus?, dismissAfterSeconds)`. Starts activities on iOS 17.2+ only (the widget extension targets 17, and the extracted App Intents metadata marks the Live Activity's button intents as introduced in 17.2; the JS wrapper checks the OS version too); guarded, ActivityKit weak-linked, the app still supports 15.1. Never throws into JS. |
| `lib/daily-tasks/live-activity.ts` | `syncLiveActivity(session, { ending, force })`, serialised. Called by the store on every session change and on each foreground (reconcile). |
| `targets/widget/FocusLiveActivity.swift` | Lock screen + Dynamic Island views. |
| `targets/widget/FocusIntents.swift` | The App Intents: Pause / Resume / 5 more minutes (Keep going) / Done (`LiveActivityIntent`, iOS 17), `StartFromWidgetIntent` (the small widget's Start), and, app only, `StartNextTaskIntent` / `StartStarterIntent`. |
| `native/app/FocusShortcuts.swift` | The `AppShortcutsProvider` (Siri, Shortcuts, Spotlight). |
| `plugins/with-focus-app-intents.js` | Config plugin: copies `targets/widget/FocusIntents.swift` and `native/app/*.swift` into `ios/<App>/` and adds them to the **app target's** Sources at prebuild. |

**Why a config plugin for the app target.** App Shortcuts are read from the
app bundle's App Intents metadata (`Metadata.appintents`), which Xcode's
`appintentsmetadataprocessor` extracts only for Swift compiled in the app
target itself, not from a pod / static library. An intent that opens the app
(`openAppWhenRun`) and a Live Activity's intent run in the app's process when
the app has them, so the same intent types must be in the app too.
`@bacons/apple-targets` only creates extension targets (its `app-intent` type
is a separate ExtensionKit extension, which can't host `openAppWhenRun`
intents or the app's shortcuts), so a ~60-line plugin adds the files to the
app target instead. `ios/` is generated (CNG); the copies are rewritten on
every prebuild. In the app, `FocusIntents.swift` gets the shared types from
`import FocusActivity` (`#if canImport(FocusActivity)`, which is also how the
file knows it's in the app: only there does it open the deep link and declare
the Siri intents).

`NSSupportsLiveActivities = YES` is set through `app.config.ts`
(`ios.infoPlist`). No push token, no new entitlements.

### Live Activity lifecycle (app side)

- **Start** when a session starts (running or paused), if
  `ActivityAuthorizationInfo().areActivitiesEnabled` and the app is in the
  foreground (a background start fails quietly; the next foreground retries).
- **Update** whenever what it shows changes: pause, resume, 5 more minutes /
  Keep going, the task's words, time's up. The content's `staleDate` is the
  countdown's end, so the views turn into "Time's up" on their own.
- **End** when the session goes: "Done" if its task was ticked, else "Timer
  stopped", shown for 8 seconds (`.after`), then dismissed. Replaced by
  another task's timer: the old one ends at once.
- **Reconcile** on every foreground: activities whose session is gone end at
  once; a running or paused session without one gets one (not one the user
  dismissed: a session that had an activity isn't given another).
- Words are cut to 120 characters (ActivityKit's 4 KB content limit).
- **Look:** lock screen is ring | caption + task (2 lines) | big time, with
  the buttons below, 14pt padding, within 160pt (measured with a render of
  the layout: 126pt, 134pt at xLarge text, 144pt at xxxLarge, with a 2-line
  task). The background is the widget's daytime indigo at every hour in light
  mode (never the morning's warm colours on the lock screen), and its evening
  colour in dark mode / StandBy. The Dynamic Island's caption for a running
  starter is the short "Just start". Captions: "Focusing" (a starter: "Just
  5 minutes", which fits the line), "Paused" (time: "4:12 left"), "Time's up"
  (a starter: "5 minutes in"); the title is always the task. The ring has no
  glyph while paused (the caption says Paused, and Resume is right there);
  its frozen arc is at half opacity, so paused never looks like running;
  at time's up it has a bell, except in the compact island, where the ring
  is on the left and the one bell on the right.
- **Buttons (PR H):** running: Pause only; paused: Resume only (no one-tap
  tick while the timer runs); time's up, in one row: **5 more minutes** (a
  starter: **Keep going**, a 20-minute timer, as the check-in; the solid
  lead), **Take a break** (a starter: **Stop for now**; hint "Ends the timer.
  The task stays open.") and **Mark done** (VoiceOver "Mark task done", hint
  "Ticks off <task>"). The three have no icons and a 14pt font (down to 0.7×
  to fit), so the lock screen keeps one button row. Mark done is never the
  loud button. On the Dynamic Island
  the solid button is the island's light indigo with dark text.
- **A tap** on the activity (lock screen or island) opens
  `dailytasks://focus?session=<id>`: the app opens that session's focus
  screen, or just Today if it has gone (`focus_opened { source: "live_activity" }`).

### Button queues (App Group)

The buttons never need the app. They run in the app's process when it can be
woken (else in the widget extension); either way they only touch the App
Group, ActivityKit and the notification centre:

- **Pause / Resume / 5 more minutes** update the mirror optimistically (a higher `rev`) and
  the activity, hold or re-schedule the end notification (a pause keeps its
  content in `focus.heldNotification*`, a resume re-adds it for the new end,
  never under a second away or past midnight; 5 more minutes on a timer
  repeats the notification that went off, at the new end), and append to
  **`focus.commands`** (`action`: `"pause" | "resume" | "extend" | "break"`; the
  buttons ignore a session from another day):

  ```jsonc
  // focus.commands (only native code writes it)
  [{ "seq": 7, "sessionId": "t_mg3k2x_ab12cd", "action": "pause", "at": 1790669100000 }]
  // focus.processedSeq (only the app writes it): the last seq it applied
  ```

  `seq` goes up by one from `max(queued, processedSeq)`; the queue keeps the
  last 50. The app applies the commands newer than `processedSeq` **before
  anything settles the session** (at launch, before `restoreSession`; on each
  foreground, and before the end timer settles it): each at its tap time (`at`,
  clamped to now), only for the current session (a stale one is dropped), and
  pause/resume are no-ops when already so, extend only acts at time's up, so
  replaying is harmless. Then it rewrites the mirror from its own state (even
  when a tap changed nothing, so a stale optimistic write is undone), re-syncs
  the activity and reschedules or cancels the end notification as usual.
- **Locking:** native writers (the widget extension, and the app process,
  which runs a Live Activity's intents) serialise read-modify-write of the
  queues and snapshot with an NSLock plus an `flock` on `FocusQueue.lock` in
  the App Group container. The app's JS only writes the "processed" marks.
- A `focus.session` with `v` above 1 (a newer app's shape) is ignored natively.
- 5 more minutes at the day-long cap does nothing, natively and in the app
  (and isn't reported as extended).

**Known limits (PR F)**
- "Keep going" on a starter from the lock screen re-schedules the one that
  went off as a timer's (its title, the task, kept; the body "Time's up.
  5 more minutes, or mark it done?" and the timer's category), at the new end. A
  timer's 5 more minutes repeats its notification at the new end. Either
  way the delivered and pending ones are removed first, and Mark done removes
  them too.
- 5 more minutes / Keep going on the lock screen with no "Time's up" left in
  Notification Center (notifications off, or the user cleared it) schedules
  nothing natively: the app schedules the new end's when it next opens.
- A Live Activity the user dismissed is remembered only while the app runs: a
  relaunch while that session is still on can show it again.
- The app's JS writes `widget.snapshot` whole without the native file lock
  (as before 1.3); a native optimistic tick can rarely be overwritten by the
  app's fresh snapshot, which is right once the tap is applied.
- **Take a break** (PR H; only at time's up) appends a `"break"` command,
  writes the mirror as `null` (the widget stops showing the timer), removes
  the end notification (pending, delivered and held) and ends the activity
  with a short "Timer ended". The app applies it when it next becomes active:
  the session clears, reported `focus_session_ended { outcome: "break" }`
  and `live_activity_action { action: "break" }`; the task stays open. A break
  in the app itself ends the activity with "Timer ended" too.
- **Mark done** appends `{ seq, id: taskId, date, done: true, source: "live_activity" }`
  to the widget's **`widget.toggles`** (so the app ticks it with the normal
  side effects next time it's active, and the session clears), marks it done
  in `widget.snapshot` for the widget, removes the end notification, and ends
  the activity with "Done". A Mark done on yesterday's activity just ends it.
- A button on an activity whose session the app has moved past shows the
  app's state (or ends the activity if the session is gone).

`live_activity_action { action: "done" | "pause" | "resume" | "extend" | "break" }` is
sent when the app applies them, only for taps that changed something (a pause
that found the time already up isn't one). Ticks from outside the app send
`task_completed { count, source: "live_activity" | "widget" }` once applied.
**A launch in the background** (a Live Activity button waking the app) does
nothing user-facing: no `app_opened` (sent on the first time the app is
active that day), no navigation or start from links (they wait until it's
active), no celebration or spoken cues.

### Start from anywhere

- `dailytasks://focus/start?task=next&source=widget|siri[&kind=starter][&id=<request id>]`.
  Any other `dailytasks://focus…` link just shows Today.
  `app/+native-intent.tsx` catches it (cold start and while running), queues
  it in `lib/daily-tasks/focus-link.ts`, and shows Today; the store acts once
  it's ready.
- Siri's intents (`openAppWhenRun`) also leave `focus.startRequest`
  (`{ id, kind, source, at }`) in the App Group, because a cold start can miss
  the link; the app takes it once ready and on each foreground if it's under a
  minute old and not the last one handled (`focus.startHandled`). The link
  carries the request's id, so both paths for one run count once. Requests
  are handled one at a time, each planned on the latest session, and a start
  never restarts a timer already running or paused on that task.
- What it does: the next open task (first open on today's list, as the
  widget shows it). No session: start it (the last length used, else 20
  minutes; `kind=starter`: the 5-minute starter), source "widget" / "siri".
  That task's timer already on (running, paused or at time's up): nothing,
  just Today. Another task's timer on: Today opens the next task's focus
  screen, which says a start there stops the other (never replaced silently).
  Nothing open: just Today.
- **Widget:** the Start button sits on the next open task: a `Link` beside it
  in the medium widget (10pt from the row); in the small one (which can't hold
  a Link) a "▶ Start" capsule (36pt, one line: it never wraps) top right, whose intent opens the app
  (`StartFromWidgetIntent`, iOS 17). The medium widget marks the timed
  task's row with a small timer glyph. Shown for
  everyone (it only opens the app); ticking stays Plus. While a session is on
  (and its task is open), the small widget shows it (the countdown top right,
  "Focusing" / "Paused" / "Time's up" and its words) and the medium one's header
  becomes the countdown (or "Paused · 4:12 left" / "Time's up"). The timeline

## PR H: ending a timer never ticks the task

Owner feedback: on the focus screen, "Done" crossed the task out, but a timer
session is often just the first sitting. The rule now: **one way off the page
at a time, and nothing ticks the task unless it says "Mark task done"** (or
"Mark done" where space is short).

- **Focus screen, no session / running / paused:** Pause/Resume and Stop
  timer as before (with a session); one exit button, **Back to Today**
  (solid; closes, the timer keeps going; hint "The timer keeps going", or
  "Closes focus mode" with none), and under it the quiet link
  **✓ Mark task done** (ticks through the normal path, then closes; hint

  Today text button are gone. "Close" became "Back to Today" with no session
