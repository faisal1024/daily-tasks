# Version 1.2: a Today screen that isn't blank

Owner-approved plan (2026-09-27/28). Goal: the lower half of Today is useful at
every hour, calm, and never a dashboard. No "missed" signals, no guilt, no hype.
Research basis: Sunsama daily rituals, Llama Life / Tiimo single-task focus,
Apple activity rings, Amabile's "progress principle" (small wins).

Version: **1.2.0** (above 1.1.0, which is in App Review).

## Shipping plan (one PR each, in order)

| PR | Scope |
| --- | --- |
| A | Time-of-day phases, "This week" row, "Done for today" card, version 1.2.0 |
| B | Coach's note (AI for Plus via a new proxy route, built-in lines for free) |
| C | "Start" focus mode on the next task |
| D | Widget redesign (independent of A–C; Swift + snapshot) |

Every PR: principal tester writes tests, three reviewers (architect + senior
iOS, usability & design, principal engineer), fix P1/P2, re-review, green CI.

## 1. Time-of-day phases (PR A)

`lib/daily-tasks/today-phase.ts`, pure:

```ts
export type TodayPhase = "plan" | "morning" | "midday" | "evening" | "done";
export function todayPhase(input: {
  taskCount: number;
  completedCount: number;
  hour: number;            // local 0–23
  eveningEnabled: boolean; // momentumSettings.eveningReflection
}): TodayPhase;
```

- `plan`: no tasks yet. Today keeps what it has now (the draft, the morning
  prompt, the ideas and brain-dump entries).
- `done`: every task is ticked off, at any hour.
- `evening`: 17:00 or later with open tasks, when the evening check-in is on.
  This must agree with `showEveningCheckIn` in `evening.ts`, so reuse its
  rule rather than copying it.
- `morning`: before 12:00 with open tasks.
- `midday`: 12:00 up to 17:00 with open tasks. It's also the fallback after
  17:00 when the evening check-in is turned off.

The lower section of Today shows, by phase:

| Phase | Lower section |
| --- | --- |
| plan | unchanged |
| morning | Coach's note (tiny first step) with **Start** on the next task (PR B/C; PR A leaves a slot), then the This-week row |
| midday | Coach's note (momentum), then "Next on your path: <next open milestone>" (tap → Progress; only when a goal path exists), then the tonight teaser ("Tonight, one tap closes the day and drafts tomorrow." Only when the evening check-in is on), then the This-week row |
| evening | unchanged: the evening check-in, then the note and tomorrow's draft |
| done | Done-for-today card, then (when the evening check-in is on) the existing check-in below it. It's shown at any hour, as it is today |

The hour must update while the app is open. Add a small hook
(`hooks/use-hour.ts`) that re-renders at the top of each hour and when the
app becomes active again. The existing `showEveningCheckIn` call reads the
same hour.

On iPad the lower section stays in the right column, and the existing
`rightHasContent` rules must include the new phases so the right column
is never empty.

## 2. Coach's note (PR B)

One short line under the three, about the **next open task**, 20 words or
fewer.

- **Kinds:** `start` (a tiny first step; used in the morning and until the
  first tick) and `momentum` (after a tick, or midday: why it matters, or
  what to do next).
- **Plus (confirmed):** one AI call when the three are set, meaning 3 tasks,
  or the day is locked with at least 1 task. It returns both lines for every
  task. The call:
  - is cached in state per day and task text;
  - is re-requested at most once more that day if the task texts change;
  - falls back to the built-in lines on any failure.
- **Free:** built-in lines on the device (no AI). They're picked stably per
  day and task, with the task text truncated to about 40 characters.
- **Proxy:**
  - a new route `coach-note` in `server/routes.mjs`, following the
    `break-down` / `evening` pattern: a provider contract in
    `server/providers/coach-contract.mjs`, the same auth, entitlement and
    per-user-limit handling as the other Plus routes, and wired into the
    worker;
  - input: `{ tasks: string[], goalTitle, tone }`;
  - output: `{ notes: [{ start, momentum }] }`, one entry per task, in order;
  - the response is untrusted: cap the length, strip control characters and
    URLs, and drop anything empty.
- **Tone:** calm, second person, no exclamation marks, no guilt ("you still
  haven't…"), no hype ("crush it"), and no emojis.
- **UI:** `components/daily-tasks/coach-note.tsx`, a quiet card with a small
  sparkle icon, the line, and (morning) a **Start** button (PR C). It
  announces itself politely to VoiceOver.
- **Analytics:** `coach_note_loaded { source: "ai" | "local" }`, sent once a
  day.

## 3. "Start" focus mode (PR C)

`components/daily-tasks/focus-mode.tsx`, a full-screen modal for a single
task. It shows:

- the task in large type, plus the coach's `start` line when there is one;
- the task's steps, which can be ticked with the same store action as the
  task row;
- an optional gentle timer: None / 10 / 25 min.
  - It's computed from a start timestamp, so it survives the app going to
    the background.
  - It uses a soft ring rather than a countdown in red.
  - At zero: one light haptic, then "Time's up. Keep going, or take a break."
  - It never auto-closes.
- **Done**, which ticks the task through the normal toggle path so the
  celebration, analytics and win-back still fire, then closes.
- **Not now**, which closes without changes.

Entry points: the Coach's note **Start** button (morning), plus "Start" on
the hero task row if it fits cleanly. It's accessible: labels, the timer
announced at start and end, and the modal traps focus.

Analytics: `focus_opened { timer }` and `focus_completed`.

## 4. Done-for-today card (PR A)

This replaces the current gradient "All three, done." card, and stays the one
gradient in the app.

- **Title:** "3 of 3. Rest is part of it." When fewer than three tasks were
  picked, it's "All done. Rest is part of it."
- **Small wins line** from history for the last 7 days, including today:
  "This week: 5 days, 13 tasks done". It uses only positive counts and never
  mentions misses. When the week has only today, it's "Your first finished
  day this week."
- When the evening check-in is on, the existing line about closing the day
  stays.
- A quiet "Pull one more from Ideas" link, **only** when there's an open slot
  and the day isn't set. It opens the Ideas sheet.

## 5. This-week row (PR A)

`components/daily-tasks/week-row.tsx`, one slim row:

- **Seven dots** for the last 7 days ending today, labelled with single-letter
  weekdays. A day is filled when the user "showed up" that day, using the same
  rule as `daysShowedUp` / Progress.
- **Today's dot:** filled once today counts, otherwise an outline ring. It's
  never shown in red or as "missed".
- **Right side:** "Day N" (daysShowedUp).
- **Tap:** opens the Progress tab.
- **VoiceOver:** "This week: 4 of 7 days. Day 24. Opens Progress."

## 6. Widget redesign (PR D)

Files: `targets/widget/*.swift`, plus a `day` field in `WidgetSnapshot`
(`lib/daily-tasks/widget-snapshot.ts`, `Shared.swift`). Old snapshots without
it must still decode.

- **systemMedium:**
  - left side: a 3-segment progress ring with a big SF Rounded numeral (done
    count) and a small "of 3";
  - right side: the tasks; the next task is bold and slightly larger, done
    tasks are faded with a filled check;
  - Plus users keep the interactive checkboxes (ToggleTaskIntent).
- **systemSmall:** ring and count, the next task, and one checkbox for it
  (Plus).
- **Lock screen:**
  - accessoryCircular: a Gauge from 0 to 3;
  - accessoryRectangular: the next task, plus a ●●○ row;
  - accessoryInline: "☀︎ 2 of 3 · Day N".
- **Background:**
  - in `.fullColor` rendering mode, a brand gradient themed by time of day:
    warm in the morning, brand indigo in the daytime, deep indigo with a moon
    glyph in the evening;
  - in tinted or clear (`widgetRenderingMode != .fullColor`), no gradient.
    Use `widgetAccentable()`, opacity and shapes so the design survives
    without colour.
- **States:**
  - all done: sun + check glyph, "All three.", "Day N";
  - empty: "Pick today's three", tapping opens the app.
- Timeline: add entries at 12:00 and 17:00 so the time-of-day theme changes
  without the app.
